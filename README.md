# Multi-Agent Decision-Making for Schnapsen

A modular multi-agent system for the card game **Schnapsen**, investigating how delegating different stages of gameplay to specialized agents affects system performance.

> **Academic project developed collaboratively with Adam Leffler as part of the Intelligent Systems course at Vrije Universiteit Amsterdam.**

---

## Overview

Schnapsen is a two-player adversarial card game that combines **imperfect and perfect information** across different stages of gameplay.

This project explores whether a game-playing system can benefit from **delegating decision-making to specialized agents**, rather than relying on a single agent throughout the entire game.

The system combines four different types of agents:

- **Rdeep Bot** — Monte Carlo-based decision making
- **Machine Learning Bot** — supervised learning from gameplay data
- **Heuristic Bot 1** — rule-based decision making
- **Heuristic Bot 2** — rule-based decision making

These agents can be assigned to different parts of the game depending on:

- the phase of the game
- whether the agent is leading or following

The resulting system, **BLiSS**, allows different agent configurations to be systematically evaluated against a strong Rdeep baseline.

---

## Research Question

> **How does the number of delegated agents influence the relative performance of a Schnapsen-playing intelligent system?**

The project investigates whether decomposing the game into specialized sub-problems and assigning different agents to these sub-problems can improve performance.

---

## System Architecture

The game was divided into four decision-making contexts:

| | Phase 1 | Phase 2 |
|---|---|---|
| **Leading** | Agent 1 | Agent 3 |
| **Following** | Agent 2 | Agent 4 |

The four contexts differ in their available information and strategic requirements.

### Phase 1

The game contains imperfect information, requiring agents to reason about possible game states and predictions.

### Phase 2

The talon has been closed and the game provides perfect information about the opponent's cards, allowing agents to focus on more deterministic strategies.

### Leading vs. Following

The leading player has greater control over the trick and can perform actions such as Marriage and Trump Exchange.

The following player has additional information because the opponent's played card is known.

---

## Agents

### Rdeep Bot

The Rdeep agent uses **Monte Carlo sampling** to estimate the best move in the current game state.

For each possible move, it simulates multiple possible game rollouts and selects the move with the highest estimated win probability.

The experimental parameters were kept constant at:

- **Samples:** 12
- **Depth:** 5

### Machine Learning Bot

The ML Bot is a supervised-learning agent that maps the current game state to a predicted move.

For this experiment, the model was trained using gameplay data generated by Rdeep agents over **1,000 games**.

### Heuristic Bot 1

A deterministic rule-based agent using heuristics based on:

- available moves
- the opponent's cards
- the player's hand
- card strength
- suit distribution

### Heuristic Bot 2

A second deterministic rule-based agent using a different set of heuristics, including decisions involving:

- Hearts Marriage
- the opponent's cards
- total hand value
- suit frequency
- card strength

## Multi-Agent Configurations

The system was evaluated at three levels of architectural complexity:

### 1. Single-agent systems

One agent controls the entire game.

### 2. Two-agent systems

Different agents are assigned to the two game phases:

    Phase 1 → Agent A
    Phase 2 → Agent B

### 3. Four-agent systems

A different agent can be assigned to each combination of game phase and player role:

    Phase 1, Leading   → Agent A
    Phase 1, Following → Agent B
    Phase 2, Leading   → Agent C
    Phase 2, Following → Agent D

In total, **39 different agent allocations** were evaluated.

---

## Experimental Evaluation

Each configuration was evaluated against the Rdeep baseline.

For each configuration:

- **10,000 games** were played
- Random seeds were controlled
- Game conditions were kept constant
- The number of games won was recorded
- The total game score was also recorded

The primary performance measure was the number of games won against Rdeep.

The secondary measure was the accumulated game score, allowing differences between narrow and decisive wins/losses to be examined.

---

## Results

The results showed that **increasing the number of delegated agents does not automatically improve performance**.

Instead, the specific allocation of agents to different roles and phases was important.

The best-performing configuration was:

### BADC

| Position | Agent |
|---|---|
| Phase 1 — Leading | ML Bot |
| Phase 1 — Following | Rdeep |
| Phase 2 — Leading | Heuristic Bot 2 |
| Phase 2 — Following | Heuristic Bot 1 |

BADC achieved:

**4,135 wins out of 10,000 games — 41.35%**

against the Rdeep benchmark.

The statistical analysis found a significant effect of the number of delegated agents on performance, with a reported **p-value of 1.3 × 10⁻⁸**.

However, the relationship was not linear: some four-agent configurations performed substantially worse than the strongest two-agent configurations.

This suggests that **careful agent specialization and allocation can be more important than simply increasing the number of agents**.

---

## Key Findings

The experiments indicated several differences in agent strengths:

- **Rdeep** performed particularly well in the imperfect-information phase when following the opponent.
- **The ML Bot** performed particularly well when leading in Phase 1, but performed poorly when following.
- **The heuristic agents** performed strongly in Phase 2, where complete information about the opponent's cards was available.
- The best overall system combined the agents according to their strongest roles rather than using the same agent throughout the game.

The results therefore support the idea that specialized agents can complement one another when their strengths are matched to specific decision-making contexts.
